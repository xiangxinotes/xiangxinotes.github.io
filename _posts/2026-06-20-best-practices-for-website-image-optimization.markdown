文字都加载出来3秒了，图片才显示出来？

一页要显示100张图片，一个一个排队加载太慢？

在这个快节奏的时代，用户的耐心极其有限。如果首屏加载超过3秒，大部分人会毫不犹豫地直接关闭页面。这不仅会导致极高的跳出率，还会让搜索引擎认为你的网站体验极差，从而大幅降低你的SEO排名和PSI评分。

所以，如果你的图片加载有了上面这些情况，那么一定要让本文帮你完美解决。

## 必须解决

快速的图片显示是网站性能的地基。如果图片加载太慢，那不管你的内容多精彩，糟糕的加载体验都会把用户拒之门外。

### 单张图片显示慢

整个网页就那么一两张图，但是文字都加载出来3秒了，图片还没显示出来？原因大概率是你单张图片的体积太大了。

这时候，你有2种选择：
- 压缩图片
- 转换图片格式

#### 图片压缩

##### TinyPNG

不用下载软件，直接打开[TinyPNG](https://tinify.cn/){:target="_blank"}就能在线压缩图片！

TinyPNG有以下优点：
- 不用注册、不用登录就能用
- 使用简单
- 能处理jpg, jpeg, png, webp 这三种常见格式
- 同一批次可以上传20张图片同时处理
- 可以批量上传和下载

不过这个工具也有一些缺点：
- 如果图片的原始大小 > 5MB 就无法处理
- 下载图片的格式和上传一样

##### Squoosh

[Squoosh](https://squoosh.app/){:target="_blank"}是谷歌制作的图片压缩工具。

Squoosh有以下优点：
- 不用注册、不用登录就能用
- 使用简单
- 能处理各种常见图片格式
- 可以直观看到压缩后图片的清晰度变化和压缩后尺寸
- 可以调整压缩参数，进行压缩对比
- 参数可以保存

Squoosh也有一些缺点：
- 每次只能处理一张图片

#### 格式转换

如果你的图片压缩后体积还是很大，TinyPNG可能帮不了你太多，但[Squoosh](https://squoosh.app/){:target="_blank"}仍旧好用，你可以用它来转换图片格式，我建议转换为webp格式。

#### 建议

两个方案，按照你的偏好选择：

- 方案A：如果网站图片太多，那就先用TinyPNG来批量压缩，之后再用Squoosh格式转换去处理那些大小不过关的图片。
- 方案B：如果你有很多时间，追求极致体验，那么直接用Squoosh完成图片压缩和格式转换。

我在更新本网站时，选的就是方案B。

### 图片个数太多

如果单张页面图片个数少，压缩和格式转换能解决你的问题。

但如果你的页面需要加载大量小图标或背景图，那么即使每张图只有几KB、几十KB，浏览器频繁发起的HTTP请求也必然会造成严重的排队延迟。

尤其是，如果你的网页首屏要展示很多图片，那用户的体感就是啥网站啊，根本啥都加载不出来嘛。这么一来，用户就流失了。

此时，你需要的是：**雪碧图**。

#### 雪碧图

雪碧图，英文名为 CSS Sprites。因为雪碧叫Sprite，所以中文翻译为雪碧图。

雪碧图其实就是一张大图，这张大图上包含散落在页面各处的单图。

假设你的网页首屏要显示50张单独的图片，那么通过合并，你可以制作1张雪碧图。50个HTTP请求瞬间就变成了1个请求，速度提升立竿见影。

之后，你再通过 CSS 来定位，就能在网页的不同位置显示不同的图片啦。是不是很棒？

说起来惭愧，我还是在最近上线的项目：[Smile Lab](https://smilelab.xiangxi.work/?utm_source=xiangxi.work&utm_medium=referral&utm_content=inline_text){:target="_blank"}（一个锻炼正向倾向的小工具，详情请看这篇文章：[《80秒重塑正向心态｜Smile Lab 帮你找回微笑，摆脱情绪内耗》](/2026/05/17/how-to-think-more-postively-use-smile-lab)）测试过程中才发现，对于首屏图片多的网站来说，压缩图片大小根本没什么用，雪碧图才是应对这种困境的锦囊妙计。

虽然我也可以自己拼图来制作雪碧图，但是我还是用了工具，我用的是[Toptal的CSS Sprites Generator](https://www.toptal.com/developers/css/sprite-generator){:target="_blank"}。

CSS Sprites Generator的使用也很简单，大致分为下面4步：
1. 把图片全部上传到左侧
1. 在Padding between elements (px) 中更改元素间距
1. 点击Download按钮下载雪碧图
1. 利用左侧提供的CSS（也可以自己写）来快速定位相关图片

在拿到第3步下载的图片之后，你还可以用Squoosh，进一步提速。

我的[Smile Lab](https://smilelab.xiangxi.work/?utm_source=xiangxi.work&utm_medium=referral&utm_content=inline_text){:target="_blank"}图片优化过程如下：
1. 将 56张 800×800 的png/webp 图片通过 Squoosh 压缩（总大小：1.6MB）；
1. 将上一步压缩后的图片通过 Toptal的CSS Sprites Generator 制作成1张 6400×5600 png格式的雪碧图（大小：48MB ）；
1. 将上一步生成的雪碧图通过 Squoosh 变为1600×1400 webp格式的图片（大小：222KB）。

其实在第3步的时候我还可以把它压缩成 800×700 webp格式的图片，这样大小就只剩 85KB了。不过我考虑 222KB 的加载根本就不算问题，还可以保留更高的清晰度，所以我没有进一步的压缩。

## 锦上添花

做好了上面的基础优化，你的网站速度已经有了质的飞跃。

下面这些图片优化，则更多是为了[Page Speed Insight](https://pagespeed.web.dev/){:target="_blank"}提分。如果你追求更高的PSI分数，那么你可以尝试下面的进阶技巧。

### 懒加载

对于首屏以下的图片，使用懒加载技术，可以让图片在进入可视区域时再加载。

图片懒加载极大地提升了首屏速度，也是我在优化本网站时学到的重要一课。

懒加载做起来十分简单，把图片
``` html
<img src="..." alt="...">
```
变为

``` html
<img src="..." alt="..." loading="lazy">
```
即可。

### 指定宽高

在首屏出现的图片元素上要明确写上 width 和 height 属性，然后配合CSS的 
``` css
width: 100%; 
height: auto;
```
来展示。

这样可以防止图片加载时造成的页面布局偏移（CLS），避免用户正在阅读时页面突然跳动。

极大程度提升用户体验的同时，也可以提升PSI评分。

本网站的logo和个人图片就是这样设置的。

### Cloudflare CDN 缓存规则

接下来要分享性能杀手锏了。

把图片托管到CDN上，再设置缓存规则，就可以让用户从离他最近的节点获取图片。这样，你的源站压力一下就减轻了，而且还能访客二次访问直接秒开，极大提升用户体验。

你可以用Cloudflare CDN设置图片文件的缓存规则。因为图片基本不会改，所以可以把缓存时间设很长，我设置了1年。

用Cloudflare缓存规则最大的好处是，就算你的文件是托管到 Github 这样的不允许用户更改缓存规则的平台上，你也可以配置Cloudflare缓存规则。方法就是：你自己买一个域名，然后接入 Cloudflare 进行 DNS 解析，再配置缓存规则即可，我就是这么干的。
